## 2. Changement et preuve de sûreté

La fonction `copy` devient `enqueue_copy` (ligne 304). Les trois `cuMemcpy2DAsync`, paramètres, ordre des plans et stream sont identiques (307–310). Son attente par sortie est retirée. `run` enfile les sorties dans le même ordre (413–416), puis attend ce stream une seule fois (421).

Pour F sorties d'une paire : **3F copies restent présentes ; F attentes finales deviennent 1, soit F−1 appels d'attente hôte retirés**. EOF/×1 conserve une attente. Le volume copié, l'arithmétique, le modèle et les pixels demandés restent inchangés. Aucun gain en ms ou FPS mesuré ou revendiqué.

Durées de vie revues dans le fichier modifié :

1. `Storage` possède les allocations CUDA et `Point` un `shared_ptr` (48–52). Chaque allocation nouvellement créée est aussi insérée dans `Context::pool` (152–160). Le pool ne réemploie que les allocations dont il est seul propriétaire (154).
2. La variable locale `points` conserve les sources jusqu'à la fin de l'attente normale dans `run` (397–421). Aucune nouvelle allocation ni aucun traitement d'étage n'est exécuté entre les copies finales et cette attente.
3. Les surfaces de sortie et d'entrée du job ont été retenues lors de `submit` (556–557). Le worker unique ne traite pas le job suivant tant que le job courant n'est pas sorti de `run` et de sa gestion d'erreur (479–498).
4. Si une copie ou l'attente lève une exception, le worker tente `cuCtxSynchronize` avant de relâcher les owners du job (492–496). Le vecteur local peut déjà être détruit, mais le pool conserve toutes ses allocations. Aucune autre tâche du worker ne peut les réemployer avant ce drainage. Les caches ne sont invalidés qu'après l'appel de drainage (493). Le traitement préexistant d'un contexte CUDA fatal reste inchangé ; aucune qualification de perte physique du GPU n'est prétendue.
5. La complétion Finished n'est construite qu'après le retour normal de `run` (490–491) ; `Job::Done` n'est publié qu'après la libération des retains du job (497). `aji_pipeline_complete_v1` ne renvoie cette complétion qu'une fois Done (560–563).
6. `drain` attend qu'il n'existe plus de job Running/Queued (500–505). `reset` draine avant ses invalidations (566–574). Le destructeur joint le worker puis synchronise le contexte avant de vider le pool (109–112).
7. Dans le lecteur actuel, `native/linux-cuda/vf_animejanai-pipeline.patch:191–205` interroge la complétion, retourne tant qu'elle est Pending, refuse une erreur, et publie les images seulement après Finished. Les images ne deviennent donc pas visibles une par une pendant les copies.

Les barrières dans `source`, Area, HDR et `aji_surface_process_v1` entre contextes restent intactes. Les règles d'aliasing des sorties sont également intactes.
