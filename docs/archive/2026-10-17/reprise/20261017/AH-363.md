1. Lire ETAT-COURANT et le reçu .93. Checkout isolé depuis .94, préserver toute installation et profil utilisateur. La .93 fraîche/AppImage contient le bon lecteur ; le défaut est la décision d’overlay d’un dossier Linux avec ancien lecteur.
2. `BuildMpvUpscale2xAnimeJaNai/LinuxMpvIdentity.cs:Capture` prend le dossier mpv réellement assemblé. Requiert mpv/libmpv.so.2 ; noms triés ordinalement ; préfixe versionné, longueurs little-endian, noms UTF8 et SHA256 des fichiers. Chaque fichier natif/build-info compte ; aucun chemin absolu, mtime ou version de scripts. Conserver framing et version si la recette évolue.
3. `Program.cs:InstallLinuxMpv` copie le build-info fourni dans mpv/build-info.txt. `WriteVersionAndManifest` utilise Capture pour Linux seulement ; Windows conserve WindowsMpvBundle.Identity/pin. Le label de capacité Vulkan déclare resident-span1 ; ne pas présenter ce label comme un hash du moteur ou une qualification AMD/Intel.
4. Ne pas modifier la règle de l’updater : `IsOverlaySufficientAsync` compare deps hors packs ; mpvfork n’est pas un pack Linux, donc son changement impose le tar complet. AppImageApplyAsync remplace déjà tout le fichier. Ne pas ajouter mpv à l’overlay sans traiter cohérence/remplacement complet des bibliothèques.
5. Contrôle existant `python3 tests/build/linux_mpv_identity_check.py <nouveau-dossier>`, puis dotnet run sur Checks.csproj généré. Il copie la vraie décision de production et utilise des dépendances réseau simulées ; aucun updater lancé. Le contrôle est déjà passé : identité stable autre path/ordre/mtime ; fichiers natifs changés invalidants ; lecteur manquant refusé ; ancien manifeste→full ; même natif/scripts/pack-only→overlay. Ne pas rejouer sans nouveau doute. Build assembleur Release déjà passé.
6. Commit explicite, release .95 et push, puis tâche indépendante. À fin de tâche vérifier CI/tag et télécharger seulement les payloads modifiés nécessaires. Dans le tar complet, recalculer Capture et comparer deps.mpvfork ; vérifier le marqueur legacy_rife_contract=1 du build-info et lecteurs. La fabrication AppImage peut réécrire des RPATH ; son identité de bundle se rapporte à l’assemblage initial, pas aux pages mappées.
7. Réutiliser qualifications moteur .93/.94 sur binaires identiques. Aucun benchmark vidéo pour cette modification de packaging. Consigner reçu et lien exact, puis Done AH363 et AH362 lorsque leur livraison couplée est vérifiée. Parent AH330 reste ouvert pour autres routes/overrides/export ; AH335 invalid-manifest distinct.
