# AH-364 — Cache CoreML transactionnel par générations

Ticket : https://tatoub.atlassian.net/browse/AH-364. Sous-ticket d’AH32, tranche CoreML d’AH254 ; ces deux parents restent ouverts. Base .97, candidate runtime ab2d0ea ; qualification native39023454995 réussie, .98 vérifiée.

1. Lire ETAT-COURANT et ce guide. Travailler dans un checkout isolé. Ne jamais supprimer le cache utilisateur pour rendre un essai concluant. Les fixtures sont dans un dossier privé et utilisent le vrai modèle déjà normalisé/livré .88.
2. `native/apple/coreml_cache_transaction.h` gère le stockage uniquement. Réutiliser les contrats communs KeyLock/mark_stage/recover_owned_stages/cache_io. La clé p3 d’AH240 ne change pas : ne pas mettre les préférences de chargement GPU/ANE dans cette clé de compilation. Le nouveau namespace `native/coreml-tx1/<programSHA256>` évite de réutiliser les anciens répertoires non transactionnels et ne les supprime pas.
3. Le fichier `current` contient exactement version, clé p3 et nom de génération sans chemin. Le lecteur refuse symlinks, formats incorrects et générations non possédées ; il ne les nettoie pas. Un hit ouvre la génération sans verrou ni écriture. Les generations conservent leur marque d’appartenance. Le chemin `model.mlmodelc` reste stable pour MLModel et le diagnostic asynchrone.
4. Sur miss : prendre le verrou stable `lock`, relire le commit, récupérer uniquement les `.stage-*` dont le marqueur appartient à la même clé, puis créer un staging unique. Une erreur de construction/validation nettoie seulement ce staging possédé. Une mort de processus libère le verrou noyau ; la demande suivante récupère l’orphelin.
5. `exec_coreml.mm` copie le package et sa table dans le staging sous le nom neutre template. Recalculer le tagV2 de cette copie et exiger le tag initial avant patch/compile. Ce nom extérieur n’entre pas dans l’identité. `mlpatch.cpp:read_table` refuse les chemins absolus et segments parents avant lecture/écriture du modèle.
6. Compiler par MLModel.compileModelAtURL, déplacer dans le staging, puis charger avec la configuration CPU indépendante pour validation native. Libérer cette validation avant promotion. Retirer les sources privées, flusher fichiers/dossiers, renommer le staging en génération unique, puis renommer atomiquement le petit commit vers current. Les anciens modèles ne sont jamais remplacés/supprimés. Une génération promue mais non publiée après crash reste conservée ; ne pas inventer un GC sans leases.
7. Charger le modèle final avec exactement les computeUnits/allowLowPrecisionAccumulation/hints préexistants. Si cela échoue, un second chargementCPU distingue artefact invalide et préférence device/hints. Si le CPU valide, garder le cache et signaler la configuration en échec. Si le CPU échoue, retirer uniquement le pointeur encore égal à cette génération sous verrou ; garder ses données et demander de rouvrir pour reconstruire. Un échec ancien ne retire pas un commit réparé par un autre processus.
8. Essais déjà conclus sur Linux : vrai protocole POSIX, commit strict, marqueurs, SIGKILL/reprise, données inconnues/autreskeys/anciennes générations conservées, stale-retire, readonly. Snapshot d’un vrai modèle : tag exact ; trois chemins de table dangereux refusés avant écriture. Ne pas rejouer ces cas sur cette même plateforme. Le workflow `qualify-coreml-transactions.yml` les porte sur macOS et exécute les seuls cas natifs CPU256 : demandes réellement chevauchées→une compilation, kill/reprise, artefact compilé invalide→retrait du pointeur puis nouvelle génération exacte, hit complet readonly. Référence RGB18df… d’AH240 réutilisée ; pas de benchmarkFPS ni nouvelle conversion.
9. Si le workflow échoue, lire d’abord receipt.json et le log du premier cas non conclu. Corriger la cause ; ne pas réexécuter les cas déjà conclus. Le driver sauvegarde chaque conclusion immédiatement. Ne jamais augmenter une tolérance d’image ; les pixels doivent rester exacts à la référence.
10. Après succès natif : versionner preuves courtes et limites, publier une release complète puis avancer sur un ticket indépendant pendant le build. Contrôler trois CI/SHA/tag/assets, le module macOS livré et sa provenance avant Done. Conserver AH254 pour autres providers/Windows et AH32 pour leurs propres critères.

Utilité attendue : cache cohérent, compilation dédupliquée, réparations sans suppression de fichiers encore utilisés. Aucun gainFPS promis. Les générations historiques conservées peuvent occuper de l’espace ; leur collecte sûre est un sujet distinct.
