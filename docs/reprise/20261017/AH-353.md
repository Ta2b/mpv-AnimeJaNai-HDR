# AH-353 — Aligner les décisions du lanceur macOS sur le plan canonique de profil

Rattachement réel AH-224 : AH-339 est déjà un sous-ticket et Jira n'autorise pas un niveau supplémentaire. Ce ticket suit son reliquat macOS ; AH-339 reste ouvert jusqu'à achèvement du contrat annoncé.

Reliquat explicite de AH-339, distinct du Manager déjà intégré dans .84 PLAYER f626ceb2154f1b90ff5c4e275e8bb31a969f1bc6. Linux AppRun et Windows utilisent le helper canonique pour les composants ; macOS garde la projection Lua commune. Il faut vérifier puis supprimer les décisions de dépendances encore divergentes, sans forcer les besoins des moteurs à converger.

1. Lire AnimeJaNaiPlatform/PlatformServices.cs (ProfileResolver, LegacyCompatible), Program.cs (--profile-plan/--profile-components), installer/macos/config/scripts/animejanai_mac.lua et les scripts de lancement/assemblage macOS. Relever le helper réellement empaqueté et son emplacement ; ne pas inventer de chemin ou exiger .NET non inclus.
2. Cartographier chaque décision macOS : modèle exact, runtime/module, étape désactivée, HDR mpv, policy RIFE et refus d'ordre non représentable. Identifier celles prises depuis le contrat partagé et celles encore dupliquées. Si tout le périmètre réel utilise déjà une projection équivalente et que cela suffit au contrat, consigner précisément cette preuve au lieu d'ajouter une couche inutile.
3. Pour chaque divergence, utiliser le plan animejanai.profile-plan.v1 comme source du modèle/runtime/capacité et de la raison d'indisponibilité. Garder l'adaptateur de commandes propre à macOS. Un groupe logique n'autorise pas l'ordre arbitraire exécuté par Linux NVIDIA ; refuser clairement les ordres non supportés, sans déplacer étapes ni convertir policies.
4. Appeler le helper au chargement/changement de profil, jamais à chaque frame. Définir erreur de lancement, timeout borné, JSON malformé/version inconnue : profil préservé, message explicite, aucun choix silencieux de moteur. Ne pas faire de scan 'un quelconque ONNX existe'. Éviter tout téléchargement lancé par une simple lecture de capacités.
5. Conserver runtime_configs et la copie privée de policy si le lecteur ancien en a besoin ; ne pas écrire dans les profils pour supprimer le global historique. HDR mpv ne requiert aucun SDK, TrueHDR reste limité à ses plateformes effectives.
6. Reprendre tests/platform/ResolvedPlan, tests/platform/profile_components_check.py et les fixtures Lua actuelles ; ajouter uniquement les cas macOS absents : modèle demandé manquant malgré un autre ONNX présent, espaces INI, étape désactivée, schéma inconnu, profil Off, policy du maillon différente du global. Contrôles CPU/routage suffisants ; pas de benchmark vidéo pour ce raccord.
7. Si le contrat partagé C# change, rebâtir le Manager depuis son player-source-ref exact puis épingler manager-source-ref dans PLAYER. Sinon garder son pin. Compiler les composants touchés puis vérifier leur présence dans le zip macOS publié ; aucune qualification Metal/CoreML GPU revendiquée par ce contrôle.

Done : consommateurs macOS couverts par le même contrat de décision, replis/erreurs explicités, tests ciblés utiles et fichiers livrés vérifiés. AH-339 parent reste ouvert tant qu'un consommateur annoncé reste divergent. To Do ; aucun nouveau code dans la préparation de ce ticket.
