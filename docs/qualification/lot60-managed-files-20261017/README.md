# AH-338 — Inventaire des programmes gérés

Le paquet fournit `managed-program-files.json`, généré depuis les octets réellement assemblés, après les transformations de plateforme. Il couvre les répertoires scripts, shaders, user-scripts, user-shaders, hdr-tools et les programmes Python/JSON de préparation. Profils, réglages, SDK, modèles et caches sont exclus par une liste de chemins admissibles indépendante du manifeste.

`ManagedProgramFiles.Sync` est partagé par le helper AppRun, le launcher macOS et l'updater Windows/Linux. Il copie/remplace un fichier seulement s'il manque ou si son empreinte correspond au reçu précédent ; il retire un fichier absent du nouveau paquet seulement si son empreinte est encore gérée. Les ajouts, modifications et liens utilisateur restent présents, avec un rapport `.managed-program-files-report.json`. L'updater respecte aussi les chemins `user_preserve` existants ; il ne recopie ensuite plus les répertoires traités par ce mécanisme.

Le reçu est publié par renommage atomique ; les copies individuelles aussi. Une interruption entre fichier et reçu converge grâce aux empreintes anciennes/nouvelles. Un verrou empêche deux synchronisations coopérantes simultanées. Toute source manquante, liée ou d'empreinte incorrecte refuse la synchronisation avant les copies. Un inventaire corrompu est une erreur explicite, jamais une autorisation de nettoyage.

Migration : le catalogue embarqué ne reconnaît que les octets programmes connus de la dernière source livrée `.84`, SHA `f626ceb2154f1b90ff5c4e275e8bb31a969f1bc6`. Les fichiers historiques inconnus sont conservés. Aucun modèle privé ni SDK n'est consulté. Un ancien script personnalisé retiré du paquet peut donc rester chargé : le rapport indique sa préservation, sa suppression appartient à l'utilisateur. Aucune migration automatique des bibliothèques GPU, traitée séparément par AH-330.

Contrôles CPU isolés : [19 cas ciblés](checks.json), dont retrait v1→v2, modifications/ajouts, migration connue/inconnue, interruption du reçu, répétition idempotente, source altérée, chemins invalides, liens de fichiers/répertoires/reçu. Le vrai AppRun avec faux mpv et helper compilé passe les32contrôles existants de packaging/IPC/préservation. Le launcher macOS exécuté avec HOME temporaire et faux mpv sous Linux passe [9cas ciblés](mac-shell-checks.json), dont retrait, fichiers personnalisés et paquet manuel sans helper. Aucun essai vidéo ni gainFPS revendiqué. Builds helper/assembleur et updater pour RIDs Linux/Windows réussis ; deux avertissements CA1416 préexistants de l'updater hors du diff.

Limites : le protocole commence avec les nouveaux paquets/outils. Il ne peut annuler les écrasements déjà réalisés par un ancien updater. Le paquet macOS émet aussi cet inventaire et utilise le même layout interne portable_config. Son launcher retire la suppression complète des répertoires scripts et préserve les ajouts/modifications ; sans helper dans un paquet manuel, il copie seulement les programmes manquants. La simulation de ce shell sous Linux ne constitue pas une exécution macOS. Les versions anciennes non cataloguées sont volontairement conservées. Le protocole assure la reprise de copies coopérantes, pas une transaction globale de tous les programmes ni une protection contre un processus hostile modifiant simultanément les mêmes chemins.
