## Faux positifs à conserver

- **Builder `SevenZipExtractor` et `SharpZipLib`** : `ArchiveFile` extrait 7-Zip, RIFE et mpv Windows ; `ZipFile`/`StreamUtils` servent aux ZIP complets et filtrés. Les chemins Linux utilisent souvent `tar`/`7zz`, ce qui ne rend pas les dépendances Windows inutiles. Les remplacer par une bibliothèque standard serait une modification fonctionnelle à tester, pas un retrait de dépendance morte.
- **Updater** : aucun `PackageReference`, uniquement BCL et source partagée `Downloader.cs`. NVML est chargé par `NativeLibrary.SetDllImportResolver`/PInvoke ; `tar`, `7za`/`7zz` sont appelés via `Process`. Ils ne peuvent pas être jugés inutilisés à partir des seules références C# statiques. La présence de deux branches overlay/full et des migrations legacy reste utile aux installations existantes.
- **Avalonia Desktop/Fonts.Inter, FluentAvaloniaUI, Material.Icons, ReactiveUI, Salaros.ConfigParser, System.Management** : usages actifs respectivement dans le démarrage, les styles/dialogues/icônes, les ViewModels/commandes, la configuration et les informations WMI de benchmark Windows. Le fait qu'une bibliothèque ne serve que sur Windows ne suffit pas à retirer sa référence multiplateforme sans adaptation de compilation.
- **`ViewLocator` et vues** : `ViewLocator.cs:12–17` résout les classes par nom (`Type.GetType`, `Activator.CreateInstance`). Les bindings XAML appellent aussi des méthodes/propriétés sans appel C# explicite. `App.Initialize` et `Program.Main` sont des points d'entrée framework, pas du code mort.
- **`AddFrucStage`** : aucune commande directe dans la vue à quatre catégories, mais usage dans `tests/ChainUx/Program.cs:35` et `tests/InterpolationStages/Program.cs:52`. La technologie FRUC demeure sélectionnable dans un maillon Interpolation. Son retrait fonctionnel demandé doit inclure parsing/migration, SDK, choix et tests ; supprimer ce seul helper ne réalise pas AH-327.
- **Modèles ONNX du Manager** : énumération dynamique par `GetAllModels`, lecture des dimensions par `OnnxInputShape`, configuration standalone copiée avec `onnx/**`. Ils ne sont pas exportés dans les paquets Manager runtime, qui choisissent seulement l'exécutable et ses bibliothèques. Leur ancien nom ou leur absence de référence littérale ne justifie pas une suppression.
- **Alias `AnimeJaNaiManager.exe`/`AnimeJaNaiManager`** : copie Windows ou lien Linux créé intentionnellement par le builder (.82 `Program.cs:969–981`) pour les raccourcis et intégrations existants. Les deux raccourcis du setup visent actuellement le même Manager. Réduire ce doublon d'interface est possible en gardant l'alias compatible ; ne pas supprimer arbitrairement l'exécutable alias ou son entrée de manifest.
- **Sources `hdr-tools-src` et workflow de décompilation** : ne sont pas une seconde implémentation HDR sélectionnable ; ils documentent la provenance du helper binaire livré. `hdr-coordinator.exe` et `display-info.dll` restent utilisés par les scripts HDR Windows. Archivage/documentation possibles, suppression non démontrée.
