# AH-356 — Coupe encodeur RIFE4.26

Outils de recherche isolés, aucune sélection runtime et aucun poids installé remplacé. Lire le reçu du modèle et le ticket avant reprise.

1. Avec Python+ONNX, lancer `tools/model-graph/split_rife_encoder.py /copie/lue/rife_v4.26.onnx /nouveau/dossier`. Seul le SHA source audité est accepté. Les nœuds/poids retenus sont identiques octet par octet ; cinq GridSample et leurs îlotsFP32 restent dans la tête. Le dossier de sortie doit être absent. Le fichier `recipe.json` identifie chaque programme et son origine.
2. Compiler le modèle original, `encoder.onnx` et `head.onnx` avec la même version TensorRT et les mêmes réglages. Pour TRT11.3 : types ONNX imposés, entrée principale `--optShapes=input:1x11x768x1280`, tête ajouter `,/encode/cnn3/ConvTranspose_output_0:2x4x768x1280`, `--builderOptimizationLevel=3 --skipInference`. Le niveau3 reproduit le défaut du réglage RIFE actuel, distinct du niveau5 des upscalers. Les anciens `--tacticSources=-CUDNN,-CUBLAS,-CUBLAS_LT` ne sont pas acceptés par TRT11 ; le backend les retire avant invocation.
3. Compiler `compare.cpp` avec C++17, headers/lib TensorRT11.3 et CUDA13 ; lier `-lnvinfer -lcudart`. Exécuter `compare reference.plan encoder.plan head.plan input.fp16`. L'entrée est un tenseur binaire FP16 `[1,11,768,1280]` :RGB A/B, t, grillesX/Y et multiplicateurs du layout v1. Le probe conserve une seule sortie encodeur et compare les synthèses complètes à .25/.5/.75. Il s'arrête au premier écart FP16/non-fini (code2), sans masquer l'écart sous une tolérance ni benchmarker un candidat non qualifié.
4. Un résultat numérique identique justifierait seulement l'étape suivante : mesure courte si un gain est revendiqué, puis ticket séparé de raccord runtime (deux bindings tête, cachefeatures15Mio, identités de paires, reset/fences/graph lifetime, fallback monolithique). Un écart exige une explication/réparation ou le rejet de cette coupe pour Quality ; les cinq raffinements ne doivent pas être remplacés par un flot médian.

Ne jamais utiliser en parallèle un build TensorRT et une mesure GPU. Le temps de build n'est pas un gain de lecture. Ces programmes ne prouvent ni la conversion couleur du lecteur ni un comportement Windows/macOS.
